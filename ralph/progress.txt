## 2026-06-11 ~16:30 UTC - US-008
- Added `DocumentSummaryResponse` and `NotebookSummaryResponse` Pydantic models in schemas.py
- Created `backend/app/routers/summaries.py` with two endpoints:
  - `POST /api/documents/{doc_id}/summarize` — generates summary for single document from all its chunks
  - `POST /api/notebooks/{notebook_id}/summarize` — generates notebook overview using probe-query chunk retrieval
- Implemented content-hash caching: SHA-256 hash of chunk texts stored alongside summary in `data/summaries/`; cache hit returned with `cached: true`, cache miss regenerates via LLM and stores new hash
- Cache auto-invalidates when document content changes (hash mismatch detected)
- LLM prompt uses low temperature (0.3) for factual summaries with 800 max tokens
- Graceful fallback when LLM is not configured: returns first 300 chars of context as preview
- Uses probe embedding ("key concepts main ideas…") with `query_chunks(top_k=8)` for representative notebook overview context
- Proper error responses: 404 for not-found documents/notebooks, 400 for empty content
- Registered router in main.py
- Files changed: `backend/app/models/schemas.py`, `backend/app/routers/summaries.py` (new), `backend/app/main.py`
- **Learnings for future iterations:**
  - ChromaDB `col.get(where={"doc_id": doc_id})` retrieves all chunks for a document — no dedicated database.py helper needed
  - Content-hash caching pattern: compute hash over sorted chunks → store with summary → compare on next request
  - The `_notebook_exists()` helper is duplicated across multiple routers (chat.py, summaries.py); could be extracted to shared utilities in a future refactor
  - Lazy imports inside endpoint bodies avoid circular import issues between routers and database module
  - Both endpoints use POST (not GET) per the spec, which is slightly unconventional but matches the generative nature of the operation
