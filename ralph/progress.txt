- **Learnings for future iterations:**
  - Custom DOM events (`window.dispatchEvent(new CustomEvent(...))`) are the right pattern for global keyboard shortcuts that need to trigger actions in deeply nested components — avoids prop drilling or context
  - When a custom event handler in a useEffect needs to read the latest props/state, use refs (`useRef`) and update their `.current` on every render — the `[]` dependency array keeps the listener stable while refs provide fresh values
  - SearchDialog already had Ctrl+K with proper focus guard — extracting it into the central KeyboardShortcuts component would have required SearchDialog's open state to be lifted up; leaving it in-place was cleaner
  - The `?` shortcut is intentionally NOT gated behind Ctrl — just pressing `?` opens the help dialog (like Slack, VSCode, and most modern apps); this is safe because it skips when focus is in INPUT/TEXTAREA
  - The app's Sidebar is always rendered in the root layout, so `notelm:new-notebook` and `notelm:open-settings` dispatch works globally; notebook-specific events (`notelm:new-conversation`, `notelm:export-conversation`) are only handled when the notebook page is mounted, which is the correct behavior

- **Learnings for future iterations:**
  - AI feature toggles use immediate localStorage persistence (unlike API settings which require explicit Save) — this allows `isFeatureEnabled()` calls in sibling components' render paths to pick up changes on next re-render without page refresh
  - The toggle changes take effect on the next render of the consuming component — e.g., after closing SettingsDialog and triggering a UI interaction (sending message, clicking document). No hard page reload needed
  - For the `ToggleSwitch` component, used inline styles for the animated circle position (`translateX`) rather than Tailwind classes since Tailwind's arbitrary values don't easily support dynamic computed transforms
  - The `Smart Titles` toggle controls whether `generateTitle()` auto-names conversations — when OFF, conversations keep their default "新对话" title; no LLM is involved in title generation currently (backend endpoint exists but isn't called from frontend)
  - When adding a new localStorage-backed setting, the pattern is: utility module exports getter/setter + constants → SettingsDialog imports for UI → consuming components import getter for conditional rendering
